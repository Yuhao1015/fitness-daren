# 训练中体验：竞品分析 P0 落地

日期：2026-10-11　依据：对 Hevy、Strong、Fitbod、Keep、训记等 13 个竞品的调研得出的 P0-1 ～ P0-4　状态：已实现

竞品分析的结论是：我们的差距在「训练中」这一段，不在分享。下面四条都只改小程序端，不需要云开发。

## P0-1 照上次（↻）

- 动作今天还是 0 组、且 60 天内练过时，「−」换成浅绿底的「↻」。点一下按上次那天的**全部已完成组**（组数和每组重量×次数）排好未打勾的组，之后只需逐行打勾。
- 每组左边：编号小圆（完成后变绿）+ 一行淡色的上次同组成绩（如 `57.5×8`），相当于 Hevy 的 PREVIOUS 列。
- 代码：`core/workout.ts` `lastSessionSets`，`core/day-ops.ts` `addSets`，`viewmodels/today.ts` 的 `canRepeat / repeatAria / rows[].prev`，页面 `onRepeatLast`。

## P0-2 打勾即开始组间休息

- 列表里把一组点成完成，底栏「已完成 x / y 组」那一行变成休息条：部位图标、大号倒计时、进度条、−15、跳过、+15。时长沿用 `restSeconds`（复合 120 秒、孤立 90 秒）；走完长振动一次。取消打勾不触发。
- 列表和专注模式共用一个计时（`core/rest-clock.ts` 的 `RestClock`，`services/rest.ts` 持有唯一实例）：在列表打勾后进专注模式、或从专注模式回列表，倒计时都接着走。之前专注模式一进页面就重置。
- 训练模式下保持屏幕常亮，离开今日页或完成训练时关掉。
- 小程序没有本地通知，切到后台不会振动；回来时按结束时间戳算剩余。界面上不暗示锁屏会提醒。

## P0-3 页头显示坚持天数

- 选部位时，页头右侧从「预计消耗 0 kcal」改成「火焰 + 已坚持 N 天」，下面两个小月亮表示**从今天起还能休几天链不断**（`core/streak.ts` `restDaysLeft`：今天或昨天练过 = 2，前天 = 1，大前天 = 0）。月亮为 0 且链还活着时，火焰轻轻跳动。训练中和完成后仍显示消耗。
- 推荐条上方加本周一到周日 7 个点：练过的用当天第一个部位的颜色，今天加圈，排了计划的未来日期用部位色描边；右端「已练 / 每周目标」。
- 完成卡片里，坚持天数旁边的月亮补满并播一次动画（「关闭动效」时不播）。按我们的规则链活着时 N 每天自然 +1，所以奖励是月亮补满，不是 N+1。

## P0-4 打勾瞬间的反馈

- 已完成的组整行变成深一档的浅绿（`ROW_DONE`，比卡片的浅绿深，否则看不出来），数字加粗变绿，勾按钮轻轻回弹。
- 这一组刷新了该动作的纪录时：勾的左上角出现小奖杯，振动从 light 改成 medium，toast 只写「新纪录 60kg」。纪录口径直接复用 `detectPRs`（`core/records.ts` 的 `exercisePR / prSetIndex`），和完成小结、海报完全一致。
- 专注模式「完成这一组」做同样的判断：破纪录时加重振动，动作名下面出现「奖杯 60kg」。

## 做的取舍（rulings）

- **照上次排出的组今天没做完，完成训练时保留不删**：报告建议丢掉，我选择保留。没打勾的组本来就不计入消耗、容量、纪录、上次成绩，保留不会污染数据；而「继续调整训练」撤销完成后还能接着打勾，删掉会丢东西。代价：完成后的小结里看不到它们，但日历里那天的记录会带着未完成的组。
- **共享休息计时放在模块单例（`services/rest.ts`），没有放进 `app.ctx`**：效果相同，不用改 `AppContext` 的类型和它的测试。
- **新纪录 toast 用文字「新纪录 60kg」**：报告写「奖杯图标 + 60kg」，但 toast 组件只支持文字，UI 规范又不用 emoji，所以用最短的两个字代替图标；行内的奖杯图标照做。
- **休息条不写「组间休息」**：用部位图标和倒计时表达，读屏文字里有「组间休息，还剩 N 秒」。

## 没验证

- 只在浏览器预览里走过：照上次、改重量打勾、奖杯与 toast、休息条倒计时、列表 ↔ 专注模式计时接续、完成后月亮补满。
- 真机上的振动强度、屏幕常亮、`.hdr-pulse` 和打勾回弹动画的观感，要在手机上看。
